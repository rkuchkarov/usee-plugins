# LLM на llama.cpp (llama)

Плагин Usee: что прямо сейчас делает llama.cpp-сервер — скорость генерации, занятость
контекста, ход текущей генерации и состояние. SDK 8.

## Как это работает
Плагин — **наблюдатель**: он только читает эндпоинты запущенного `llama-server`
(GET `/props`, `/slots`, `/metrics`); промптов и запросов он не отправляет вовсе.
Состав эндпоинтов плагин берёт из самого сервера — из `/props`.

- `GET /props` — раз в 60 с (и сразу после серии неудач): модель, `total_slots`,
  потолок `n_ctx` слота, карта включённых эндпоинтов.
- `GET /slots` — каждый тик: `is_processing`, `n_prompt_tokens`, `n_ctx`,
  `next_token[0].n_decoded` / `n_remain`. Из нескольких слотов (`--parallel`) берут
  генерирующий, иначе — самый занятый; сколько слотов, видно в строке статуса.
- `GET /metrics` — редко (45 с): накопительные итоги и честная средняя за запрос.
  Каждый скрейп обнуляет окно средних на сервере, потому и не спрашивают чаще.
  Одна дополнительная съёмка — сразу после конца запроса: сервер дописывает его
  метрики только тогда, и ждать следующего редкого опроса значило бы показывать
  прошлое.

Скорость — дельта счётчика токенов между опросами. Оценок по `Δ n_prompt_tokens`
нет: на живом замере они дают 0 при сотнях сгенерированных токенов. Если счётчик за
тик не сдвинулся (сервер читает длинный промпт) или форк на прелифе гасит свою
скорость до `0`/`null` — это не «0 ток/с», а отсутствие измерения: на карточке
остаётся последнее измеренное число, а в кривую точка не идёт (старые точки сами
выходят из окна).

Ступени возможностей (берётся первая доступная): `next_token.n_decoded` из `/slots` →
счётчик адаптера форка → счётчик из `/metrics` → только `is_processing` + `n_ctx`. Нет
счётчика — карточек скорости и генерации нет, а не нули. Счётчик из `/metrics` живых
токенов не даёт: сервер выставляет его только в конце запроса, поэтому при нём одном
ход генерации остаётся невидимым, а итог и средняя приходят сразу после его конца.
Попадание в кэш считаем как `кэш / (обработанные + кэш)`: `prompt_tokens_total` в
llama.cpp не включает кэш.

## Карточки
- **spark «скорость»** — ток/с и кривая (масштаб по максимуму окна, держится в `ctx.storage`);
- **gauge «контекст»** — занятый KV-контекст и потолок слота;
- **progress «генерация»** — токены текущей генерации, процент, если лимит виден
  (`n_remain`), иначе индикатор без краев; `≈N с` до конца и «2 мин назад»;
- **status «состояние»** — псевдоним модели, бейдж `ГЕНЕРИТ` / `ЧТАЕТ` / `ПРОСТОЙ` /
  `СОН` / `ОБРЫВ`, и 4-й строкой — итоги с запуска («с запуска 7,5 млн ток»).

Итоги с запуска едут в `detail` статус-карточки именно потому, что у gauge футера нет.
Прошивка рисует четвёртую строку не на всякой ширине: строка видна на широких
status-карточках.

## Сущности
`llama.tok_s`, `llama.context_used`, `llama.context_size`, `llama.tokens_generated`,
`llama.tokens_total`, `llama.cache_hit`, `llama.busy`, `llama.state` (состояния:
«ожидает», «читает запрос», «генерирует», «нет связи»). Объявлены все — значения идут
только тем, кто их потребляет, и пересобираются при изменении спроса.

## Настройки
| Ключ | Тип | Назначение |
|------|-----|-----------|
| `addr` | string | адрес сервера, `host:port` (по умолчанию `127.0.0.1:8080`) |
| `apiKey` | secret | ключ `--api-key`: шлётся как `Authorization: Bearer …` **только если заполнен** |
| `intervalSec` | number | период опроса `/slots`, 1–60 с (по умолчанию 2) |
| `forkMetrics` | select | `auto` — сам разберёт Prometheus или JSON форка; `prometheus` — только Prometheus; `off` — `/metrics` не читать |

## Права
```json
"permissions": { "net": ["setting:addr"] }
```
Один хост из настройки `addr`; никаких других адресов плагин не видит.

## Что видит человек, если сервер урезан
| Сервер | Что теряется | Что в статусе |
|--------|--------------|---------------|
| `--no-slots` (501 на `/slots`) | токены, скорость, генерация | «слоты закрыты: запускай llama-server со --slots» |
| без `--metrics` (501 на `/metrics`) | итоги с запуска, средняя сервера | молча: остальное считает `/slots` |
| `/slots` без `next_token` + `--metrics` | ход генерации: токены и скорость видны только после конца запроса | «токены не видны» |
| `/metrics` нераспознанный | счётчик, если `/slots` тоже молчит | «метрики не распознаны» |
| `--api-key`, ключ не вписан (401/403) | всё | «сервер требует ключ — впиши API-ключ в настройки» |
| сервер не отвечает | всё, карточки держат последние числа | «llama-server не отвечает на <адрес>» |

Строка статуса всегда заканчивается подписью источника метрик: `метрики: Prometheus`,
`метрики: адаптер «…» (не стандарт)` или `метрик нет`.

JSON-адаптер `/metrics` форков — **не стандарт llama.cpp**: он только добавляет
возможности (токены, скорость, потолок контекста), помечен в статусе и отключается
настройкой `forkMetrics`.
Значения адаптер берёт только с верхних уровней JSON (максимум по всему телу выдал бы рекорд
из истории запросов за текущее), а чужие накопительные итоги не трактует: у разных форков
«prompt_tokens» то включает кэш, то нет — при адаптере строки «с запуска» и доля кэша молчат.
Формат узнаётся по **именам** полей (`hardware_static`, `prefill_tok_s_mean`), а не по их
значениям: в простое `live.tok_s` и `live.generated` равны `null`, и по значениям адаптер
исчезал бы между тиками.

## Требования
Агент с SDK 8 (Usee ≥ 1.5.0) и запущенный `llama-server` (или совместимый): `/props` и
`/slots` включены по умолчанию, `--metrics` и `--api-key` — по желанию.

## Локальная проверка
Агент → «Плагины» → **＋ «Плагин из папки разработки…»** → эта папка; без запущенного
сервера плагин запустится и честно скажет, что до адреса не достучался. Из консоли:
`bash tools/usee-plugin.sh validate plugins/llama`.
